## 0. House rules

**Releases**
- `main` is production (Railway, portal.rypacademy.com). `develop` is staging (Railway, rypacad.ryptest.com), and **staging uses the production database**.
- Agents merge into local `develop` only. They never push and never deploy.
- The owner pushes:
  - `git push origin develop`, then checks on staging;
  - then `git push origin develop:main`.
- The owner runs Firebase deploys from the main checkout (`rypacad`), never from a `wt-*` worktree:
  - always `npx firebase-tools deploy --only <targets> --project rypacad` (there is no global `firebase` on this machine);
  - functions are 1st gen and pin a secret's version at deploy, so after `secrets:set` the function has to be redeployed;
  - order when a change spans layers: functions, then rules/indexes, then the push.
- Hand the owner commands in the final message of a turn, one per code block, each prefixed with `cd C:\Users\Mac\Desktop\rypacadapp\rypacad &&`.

**Production data**
- Real families have used the app since Oct 1, alongside test households.
- Read-only production probes are fine. Production writes are not.
- Scripts that write production (`scripts/*.mjs` with `--prod`): agents run `--dry-run` only; the owner runs `--yes`.
- Never create accounts on production. Refunds, money movement and permanent deletes are the owner's.
- Check every cancel or delete against the real households first.

**Secrets and local config**
- `localhost:3000` runs the main checkout's `frontend/.env`, which is **live production config**. Never start, open or sign in there.
- Worktrees run the dev server on 3005 with `REACT_APP_USE_EMULATORS=true BROWSER=none`.
- Never read, print or copy `frontend/.env`, `functions/.env*` or `functions/.secret.local`.
- `scripts/lib/prod-auth.mjs` may be imported, never read or copied.
- The functions emulator pulls the real secret from production Secret Manager when a bound secret is empty locally. Worktrees need placeholder values in `functions/.secret.local` and no `SMTP_HOST`.
- Never paste an Alta door "API link" anywhere (chat, logs, docs). It opens the front door.

**Code**
- Repo files are CRLF.
  - Edit them with a normalize/restore helper (read, convert to LF, replace, convert back), never `sed -i`.
  - Check with `file <path>`.
- Files stay under 500 lines; put new UI in a new file when one is close.
- Write the test first.
- No real family names in code, tests, commits or docs.
- Commit trailer as the team uses it.

**Worktrees**
- Worktrees junction `node_modules` to the main checkout.
- Remove the junctions before `git worktree remove`; a recursive delete through a junction empties the main checkout's `node_modules`.
- Dedupe and cleanup tools treat `wt-*` as duplicates, so never run them mid-sprint.
- `wt-family-page` (`feat/staff-family-page`) belongs to another session's work on unifying the staff family screens. Leave it alone unless the owner hands it over.

**Gates** (all must pass before a merge into develop):
```
cd frontend && CI=true npx react-scripts test --watchAll=false
cd frontend && npx eslint src        # only src/setupTests.js:18 globalThis is allowed
cd frontend && npm run build         # if Git Bash segfaults in npm, run it from PowerShell
cd functions && for f in portal/*.test.js; do node $f > /dev/null 2>&1 || echo FAIL $f; done
node functions/test/check-exports.js
node --test scripts/test/*.test.mjs
```

**Writing for the owner and for families**
- The owner wants short replies that lead with the question; leave out hashes, counts and paths unless asked.
- The Saturday competition is "RYP Tour" or "Tour event" in user-facing copy; internal ids keep `tournament`.

**Owner rulings:**

**Proven on Nov 17:** a staff unlock opened the door (log line `unlockDoor: opened ... altaStatus=204`).

**Left for the owner, at the academy:**
1. On the staff screen, tap "Use this phone's location", then Save.
2. Switch the mode to Everyone.
3. Set Alta's **Entry open duration** for the entry to the same time as the staff screen's open time.

**Alta facts that cost a day:**
- The door's open time is the entry's *Entry open duration*.
- It is **not** the Cloud Key credential's *Max duration*. That field caps how long a link may live, so a short value kills the link: Alta answers 400 "Token error".
- To replace the link:
  1. make a new Cloud Key with no cap and generate a new API link;
  2. run `npx firebase-tools functions:secrets:set ALTA_UNLOCK_URL --project rypacad`;
  3. redeploy `functions:unlockDoor`.
- The emulator never calls Alta: it returns a fake 204 with `DOOR_FAKE_ALTA=1`, and `misconfigured` otherwise.

### 2.5 Verification email deliverability (decision pending)

**Problem.** Families report the "verify your email" message landing in Spam or not arriving. A password login can't pay until it is verified.

**Facts:**
- Firebase Auth's default mailer sends as `Portal@rypacad.firebaseapp.com`: SPF pass, DKIM `d=firebaseapp.com` (not aligned), no DMARC.
- Template edits are locked (`EMAIL_TEMPLATE_UPDATE_NOT_ALLOWED`).
- The app used to tell families to search Spam for `noreply@`. That copy is fixed (`authCopy.js`, now live).
- **Firebase's hosted email links carry the OLD browser key (ends rkcc).** Never delete that key while this holds.
- The delivery readout is Cloud Monitoring, `serviceruntime.googleapis.com/api/request_count` for identitytoolkit by method:
  - `GetOobCode` = Firebase accepted the send;
  - `SetAccountInfo` = the link was used.

**Unblocking a stuck family.** Run `node scripts/mark-email-verified.mjs --prod --email <address>`, `--dry-run` first; the owner runs `--yes`. Five stuck families still need their addresses confirmed first; the owner has the names.
